# Личный ритм

Веб-приложение для плана тренировок, рецептов, отметок о выполнении, воды и динамики веса. Работает в браузере на телефоне и компьютере; Expo для использования приложения не нужен.

## Текущий статус размещения

- **Рабочая версия:** Replit. Интерфейс и API доступны через `https://workout-app-web--kriptogelo.replit.app`; для доступа из некоторых сетей может потребоваться VPN.
- **GitHub Pages:** ещё не опубликован. GitHub Pages размещает только файлы интерфейса, но не API и не базу данных.
- **Исходный код:** публичный репозиторий GitHub. Он не содержит паролей, токенов пользователей или их журналов.
- **Установка на телефон:** откройте сайт в Safari или Chrome и выберите «На экран Домой» / «Установить приложение». Для синхронизации данных устройству нужен интернет.

## Бесплатный вариант размещения

Подготовлен `render.yaml` для API на Render Free. Для PostgreSQL используйте Neon Free, а не Render Postgres: бесплатные базы Render удаляются через 30 дней. Render Free останавливает API после 15 минут без запросов; первый запрос после паузы может ждать около минуты. Render указывает, что бесплатный тариф предназначен для тестовых и хобби-проектов, а не для критичных production-сервисов.

Neon Free не имеет срока окончания, но ограничен 1 ГБ на базу и месячными лимитами вычислений. Доступность Render, Neon и `github.io` без VPN нужно проверить именно из вашей сети; гарантировать её заранее нельзя.

### Первоначальная настройка

1. Создайте бесплатную базу PostgreSQL в [Neon](https://neon.com/). Скопируйте её connection string; не публикуйте его и не добавляйте в файлы репозитория.
2. Создайте в [Render](https://render.com/) Blueprint из этого репозитория. Render прочитает `render.yaml` и запросит `DATABASE_URL`; укажите connection string Neon. Не создавайте Render Postgres.
3. В GitHub откройте **Settings → Secrets and variables → Actions → Secrets** и создайте секрет `DATABASE_URL` с тем же connection string. Затем вручную запустите workflow **Initialize database schema** один раз для новой пустой базы. Workflow создаёт таблицы; не запускайте его с URL базы, содержащей важные данные.
4. После успешного запуска API возьмите его HTTPS-адрес Render. В GitHub откройте **Settings → Secrets and variables → Actions → Variables** и задайте `VITE_API_BASE_URL` значением origin API, без `/api`.
5. В **Settings → Pages** выберите **GitHub Actions**, затем вручную запустите **Deploy GitHub Pages**. После этого адрес интерфейса будет `https://olkosarau.github.io/workout-app/`.

Новая Neon-база будет пустой. Данные и аккаунты из Replit или старой локальной базы Expo автоматически не переносятся. Оставьте текущую версию Replit без изменений, пока новая не проверена.

Переменная `VITE_API_BASE_URL` не является секретом: её значение попадёт в собранный JavaScript. Не указывайте в ней пароль, токен или URL с учётными данными. Пароль Neon храните только в секрете GitHub Actions и в защищённых настройках Render.

API уже разрешает запросы с `https://olkosarau.github.io`. Если подключите собственный домен Pages, добавьте его в `CORS_ALLOWED_ORIGINS` на Render.

## Локальная разработка

В Replit запущены два сервиса: веб-приложение и API. Схема базы разработки применяется командой:

```sh
pnpm --filter @workspace/db run push
```

Для сборки интерфейса задайте `PORT` и `BASE_PATH`; GitHub Actions уже использует `PORT=4173` и `BASE_PATH=/workout-app/`.

## Важное о старых данных

Старая локальная база из Expo/SQLite не входит в репозиторий и не переносится автоматически. После запуска центрального API нужно зарегистрировать аккаунт заново; старые отметки, вес и профили останутся на прежнем устройстве, пока их отдельно не экспортировать.
